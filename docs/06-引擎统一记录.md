# 引擎是怎么从「能用」变成「做好」的

## 结论先说

**现在不需要任何参数：**

```bash
flutter build linux --debug
flutter build linux --release
```

两条都能跑，产出能正常渲染的应用。不需要 `--local-engine`，不需要 `--no-tree-shake-icons`，
不需要改 kernel hash，没有 `gen_snapshot` 包装脚本。

---

## 「能用」和「做好」的区别

之前的状态：

| | 之前 | 现在 |
|---|---|---|
| `flutter build linux` | ❌ 报 `gen_snapshot` 找不到 | ✅ 直接过 |
| 必须加的参数 | `--local-engine-src-path` + `--local-engine` + `--local-engine-host` | 无 |
| release 图标裁剪 | ❌ 必须 `--no-tree-shake-icons` | ✅ 正常裁剪 |
| debug kernel hash | ❌ 手改 177 段 dll header | ✅ 天然对齐 |
| release AOT | ❌ `gen_snapshot` 套包装脚本 | ✅ 原生 ELF |
| Dart SDK 版本 | `dart` 40.0 / VM 51.0 **混用** | 全部 51.0 |

---

## 根本原因：源码是 51.0，二进制是 40.0

`flutter/third_party/dart/tools/VERSION` 写着：

```
CHANNEL dev
MAJOR 3
MINOR 15
PATCH 0
PRERELEASE 51          ← 源码是 51.0
PRERELEASE_PATCH 0
```

但 `deps/dart-sdk`、`src/flutter.tmp/bin/cache/dart-sdk`、`flutter-tool/bin/cache/dart-sdk`
**全是 `3.15.0-40.0.dev`**（Fri Oct 16 构建）。

而 `gen_snapshot` 和引擎 `.so` 是 `3.15.0-51.0.dev`（Mon Oct 19 构建）。

**所以引擎到底是用 51.0 编的，但配套的 dart-sdk 二进制是 3 天前的旧产物。**

additionally：所有 dart-sdk 里的 `version` 文件都写着 `3.15.0-51.0.dev` ——
说明这个目录本来是 51.0 的，只是 `bin/` 下的二进制被换成了 40.0 的。版本文件和二进制不自洽。

---

## 修法：从源码重建 SDK

### 为什么不能直接下个 51.0 的包

Flutter 从不发布 riscv64 产物，`storage.googleapis.com/.../linux-riscv64/...` 一律 404。
板子上也没有 51.0 的 dart-sdk 压缩包（`/tmp/dartsdk.zip` 是 40.0 的）。

**只能从引擎源码自己编。**

### 用到的 ninja 目标

```bash
cd src/flutter.tmp/engine/src/out/riscv64-release

# 1. 完整 SDK（3704 步，约 55 分钟）
ninja "flutter/third_party/dart:create_sdk"
```

注意目标名里的**冒号**——GN 用 `toolchain:target` 语法，build.ninja 里是
`build flutter/third_party/dart$:create_sdk`（`$:` 转义一个字面冒号）。

这一步会撞一个坑：`gen/analysis_server.dart.snapshot` 失败，

```
PathNotFoundException(path=.../flutter/third_party/dart/sdk/version; Cannot open file)
```

修法：

```bash
printf '3.15.0-51.0.dev' > src/flutter.tmp/engine/src/flutter/third_party/dart/sdk/version
```

⚠️ 但这一步（3704 步）实际上我们**没跑完**——它太重，而且在 `analysis_server` 上又挂了一次
（这次是 `Bad state: Future already completed`，analysis_server 自己的 bug，与我们无关）。

### 更省的路径：只编必需的部分

`create_sdk` 会连 `analysis_server` / `dart2js` / `dartdevc` 这些**开发工具**一起编，
对一个只要跑 `flutter build` 的引擎来说是浪费。

我们最终用的是 **1240 步**的子集：

```bash
BIN="dart-sdk/bin/dart dart-sdk/bin/dartaotruntime dart-sdk/bin/dartvm dart-sdk/bin/dartcliruntime"
LIB=$(ninja -C $O -t targets all | grep -E "^dart-sdk/lib.*: copy$" | awk -F: '{print $1}')

ninja -k 0 $BIN $LIB        # -k 0 = 单点失败不中断
```

`-k 0` 很关键：这样即使某个非必需目标挂了，其余目标仍会完成。

### 还要重建两样东西

光有 SDK 二进制不够，有两处快照是用旧 SDK 编的：

**1. `flutter_tools.snapshot`**（flutter 工具本体）

换完 SDK 后第一次跑 flutter 会报：

```
Wrong full snapshot version, expected '919077dd58aa24c9911491c7834311ad'
                          found '79a41e9b2f8c9e7c2c2353277718f1b6'
```

其实是 flutter 工具自己的快照版本对不上。强制重建：

```bash
rm -f bin/cache/flutter_tools.stamp bin/cache/flutter_tools.snapshot
flutter --version      # 自动重建，约 10 分钟
```

成功后会打印：

```
Tools • Dart 3.15.0 (build 3.15.0-51.0.dev) • DevTools 2.61.0
```

**2. `frontend_server_aot.dart.snapshot`**（决定 kernel 的 SDK hash）

```bash
cd out/riscv64-release
ninja frontend_server_aot        # 383 步，约 7 分钟
cp frontend_server_aot.dart.snapshot $FLUTTER_ROOT/bin/cache/dart-sdk/bin/snapshots/
```

**这一步是 kernel hash 天然对齐的关键。** 之前 hash 不符（`5521341774` vs `69672e35b9`）
就是因为这个快照是 40.0 编的。

## 补齐 artifact 目录

flutter 按 `_getEngineArtifactsPath()` 找文件：

```dart
// mode == debug || mode == null  →  linux-riscv64
// mode != debug                  →  linux-riscv64-<mode>
```

所以：

- **`artifacts/engine/linux-riscv64/`** = debug 引擎 + **宿主工具**
- **`artifacts/engine/linux-riscv64-release/`** = release 引擎
- **`artifacts/engine/linux-riscv64-profile/`** = profile（我们没有，留空）

每个目录需要（我们一开始只有 3 样，缺 5 样）：

```
libflutter_linux_gtk.so          ✅ 原有
icudtl.dat                       ✅ 原有
flutter_linux/  (26 个头)        ✅ 原有
gen_snapshot                     ← 缺
impellerc                        ← 缺
font-subset                      ← 缺
frontend_server_aot.dart.snapshot ← 缺
shader_lib/                      ← 缺
```

### `shader_lib` 的坑

`impellerc` 编译着色器时要找 `flutter/runtime_effect.glsl`，
路径是 **`impellerc` 同级的 `shader_lib/`**：

```dart
// shader_compiler.dart:223
final String shaderLibPath = _fs.path.join(impellerc.parent.absolute.path, 'shader_lib');
```

不放进去就报：

```
error: '#include' : Included file not found. for header name: flutter/runtime_effect.glsl
```

```bash
cp -af out/riscv64-release/shader_lib $C/linux-riscv64/shader_lib
```

### `font-subset` 也是自己编的

```bash
ninja font-subset          # 73 步
```

它会连 harfbuzz 的 subset 静态库一起编。产出的 `font-subset` 1,377,872 B，
用法 `font-subset <output.ttf> <input.ttf>`，codepoints 从 stdin 进。

有了它，`flutter build linux --release` 默认的图标裁剪就能正常工作，
不用再加 `--no-tree-shake-icons`。

## 最终一致性核验

```
flutter          : Flutter 3.41.0
dart             : 3.15.0-51.0.dev on "linux_riscv64"
dartaotruntime   : 3.15.0-51.0.dev on "linux_riscv64"
dartvm           : 3.15.0-51.0.dev on "linux_riscv64"
gen_snapshot     : 3.15.0-51.0.dev on "linux_riscv64"
engine .so       : 3.15.0-51.0.dev
```

四项全部 51.0，这才叫一致。

**`gen_snapshot` 是原生 ELF**：

```
file gen_snapshot → ELF 64-bit LSB pie executable, UCB RISC-V
```

不是脚本。之前的包装脚本已删除。

## 效果

| 构建 | 耗时 | 结果 |
|---|---|---|
| `flutter build linux --debug` | 412 秒 | ✅ kernel hash `69672e35b9` 天然对齐，渲染正常 |
| `flutter build linux --release` | 659 秒 | ✅ `libapp.so` 15,729,544 B，bundle 66 MB，图标裁剪生效，渲染正常 |

应用运行证据：窗口 400×500、三个 isolate 就绪、`Server started (Port: 53317, HTTPS only)`、
截图 35,969 B（空白基线是 4,956 B）。

## 还没做的

- **`linux-riscv64-profile/` 是空的** —— 没编 profile 引擎，`flutter build linux --profile` 会失败
- **`analysis_server` 快照没编出来** —— 它自己内部 bug，不影响构建，但 `dart analyze` 之类可能受影响
- **从零干净重建未验证** —— 上面所有步骤都是从「已有 out 目录」出发的增量构建。
  换一台干净机器按文档走能不能成功，**还没测**
- **`dartcliruntime` 仍是 40.0** —— 我们的子集里它的拷贝目标没跑到。目前没用到，但严格说是个残留

最后一条要诚实：**「做好」是指「装好就能直接编、编出来能用」，不等于「可复现」。
可复现还需要一次从零构建验证。**
