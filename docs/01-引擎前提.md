# 引擎前提：它从哪来，现在缺什么

本仓库**不含** Flutter riscv64 引擎。这份文档说明引擎必须满足什么条件，以及我们这台的实测状态。

---

## 一、为什么必须有自建引擎

LocalSend 桌面 GUI 是 Flutter 应用。`flutter build linux` 之前会去下载：

```
https://storage.googleapis.com/flutter_infra_release/flutter/
  <engine-revision>/linux-riscv64/artifacts.zip
```

**这个文件不存在**，服务器返回 404。Flutter 从未发布 riscv64 Linux 产物。

所以要么自建，要么走 CLI / 网页直传那两条路。

---

## 二、引擎必须提供的三样东西

一次能跑通 GUI 构建的引擎，至少要有：

| 组件 | 用途 | 我们的状态 |
|---|---|---|
| `libflutter_linux_gtk.so` | GTK embedder，应用真正链接的库 | ✅ debug 425 MB / release 14 MB |
| `gen_snapshot` | release 的 AOT 编译器 | ✅ 5.4 MB |
| `flutter_linux/*.h` | 26 个公开头文件（含 umbrella `flutter_linux.h`） | ✅ |

`flutter build` 还会找这些，我们**没有**：

| 组件 | 缺失的后果 |
|---|---|
| `font-subset` | release 必须加 `--no-tree-shake-icons` |
| `impellerc` | 在 `out/` 有，但没进 cache artifact 目录 |
| `frontend_server_aot.dart.snapshot` | 同上 |
| `const_finder`、`snapshot_deps` | 暂未用到 |

---

## 三、`--local-engine` 是关键词

**我们的引擎不在 Flutter 缓存里，只能靠参数指过去。**

```bash
flutter build linux --release --no-tree-shake-icons \
  --local-engine-src-path=/root/flutter-riscv64-engine/src/flutter.tmp/engine/src \
  --local-engine=riscv64-release \
  --local-engine-host=riscv64-release
```

三个参数缺一不可：

- `--local-engine-src-path`：引擎源码根（`out/` 的父目录）
- `--local-engine`：`out/` 下的目录名
- `--local-engine-host`：不给的话只打印警告就退出

`cache.dart` 里有一句短路，所以 `--local-engine` 能跳过引擎 artifact 校验：

```dart
if (isLocalEngine && artifact is EngineCachedArtifact) { ... }
```

**但 `flutter pub get` 不认这三个参数**，它照样会去下载、照样 404。
所以还必须伪造缓存 stamp，见第五节。

---

## 四、实测：不带 `--local-engine` 会怎样

```
$ flutter build linux --release --no-tree-shake-icons
Building Linux application...
ERROR: Target aot_snapshot_release failed:
  ProcessException: Failed to find
  ".../bin/cache/artifacts/engine/linux-riscv64-release/gen_snapshot"
  in the search path.
Build process failed
```

因为 `bin/cache/artifacts/engine/linux-riscv64-release/` 里只有：

```
flutter_linux/            ✅
icudtl.dat                ✅
libflutter_linux_gtk.so   ✅
```

缺 `gen_snapshot` —— 这就是「引擎能用但没装好」的直接证据。

### 补齐方法（尚未验证）

```bash
E=/path/to/engine/src
C=$FLUTTER_ROOT/bin/cache/artifacts/engine
for v in "" -profile -release; do
  D=$C/linux-riscv64$v
  cp $E/out/riscv64-release/gen_snapshot                        $D/
  cp $E/out/riscv64-release/impellerc                           $D/
  cp $E/out/riscv64-release/frontend_server_aot.dart.snapshot    $D/
  cp $E/flutter/shell/platform/linux/public/flutter_linux/*.h   $D/flutter_linux/
done
```

补完之后不带 `--local-engine` 应该能过 artifact 校验。**这条路径没实测过**，写在这里是为了让下一个人少走弯路。

## 五、必须伪造的缓存 stamp

`pub get` 不看 `--local-engine`，它检查 `bin/cache/<name>.stamp` 的内容是否等于
`cache.engineRevision`，不等就触发下载。

```bash
C=$FLUTTER_ROOT/bin/cache
V=$(cat $C/engine.stamp)          # 例：57d5122cd9dcfd0174ba963e61df20a328378c64
for n in font-subset flutter_sdk linux-sdk engine engine-dart-sdk; do
  echo "$V" > $C/$n.stamp
done
```

对应 `flutter_tools/lib/src/flutter_cache.dart` 里三个类：
`FlutterSdk`（`flutter_sdk`）、`LinuxEngineArtifacts`（`linux-sdk`）、
`FontSubsetArtifacts`（`font-subset`）。它们都 `extends EngineCachedArtifact`，
`version` 都取 `cache.engineRevision`。

还要确保这些目录存在（`isUpToDateInner` 会检查）：

```
bin/cache/pkg/{sky_engine,flutter_gpu}
bin/cache/artifacts/engine/common/{flutter_patched_sdk,flutter_patched_sdk_product}
bin/cache/artifacts/engine/linux-riscv64{,-profile,-release}
```

另外 `flutter --version` 若报 `0.0.0-unknown`，说明 clone 没有 git tag，需要：

```bash
cd $FLUTTER_ROOT && git tag -f 3.41.0
```

## 六、我们这个引擎的已知缺陷

### Dart SDK 版本不一致 ⚠️

| 组件 | 版本 |
|---|---|
| `deps/dart-sdk`（编 kernel 用） | **3.15.0-40.0.dev** |
| `gen_snapshot`（AOT 用） | **3.15.0-51.0.dev** |
| 引擎 `.so` 内含 | **3.15.0-51.0.dev** |

正常引擎里这三者必须完全一致。我们这份不一致，导致三个 workaround：

1. **177 段 kernel hash 要手改**

   `flutter build` 产出的 `kernel_blob.bin` 是多段 dill 顺序拼接，
   每段 header 有 10 字节 SDK hash。只改第一个会失败：
   ```
   Dart Error: Can't load Kernel binary: Invalid SDK hash.
   ```

2. **`gen_snapshot` 要套包装**

   release 构建时 `frontend_server` 会把 `app.dill` 覆盖回旧 hash，
   直接编报 `ApiError` / exit 254。见 `engine-notes/gen_snapshot-wrapper.sh`。

3. **release 必须 `--no-tree-shake-icons`**

   因为 `font-subset` 缺失，与版本不一致无关，但同样是个坑。

### 从未验证从零重建

整个引擎构建过程有大量手工干预：clang wrapper 加 `--rtlib=compiler-rt`、
`/usr/include/pci` 软链、LTO 步骤加 `-fuse-ld=lld`、astcenc 源码从 codeload 拉、
18 个手工 stamp。

**换一台机器按文档走一遍能不能成功，没人知道。** 这一条是引擎能不能算「交付物」的分界线。

---

## 七、想真正做「好」引擎，还差四步

1. 把 `gen_snapshot` / `impellerc` / `frontend_server_aot` / 头文件铺进三个 cache 目录
2. 编出 `font-subset`
3. **统一 Dart SDK 版本**（做完后 177 段 hash 补丁和 wrapper 全部可删）
4. 从零干净重建一次，验证可复现
