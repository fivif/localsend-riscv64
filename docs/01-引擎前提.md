# 引擎前提：需要什么，怎么算完备

本仓库**不含** Flutter riscv64 引擎。这份文档说明引擎必须具备什么才能让
`flutter build linux` 正常工作，以及如何判断自己的引擎是否完备。

> 我们这台引擎已经补齐完成，过程见 [`06-引擎统一记录.md`](06-引擎统一记录.md)。

---

## 一、为什么必须有自建引擎

LocalSend 桌面 GUI 是 Flutter 应用。`flutter build linux` 之前会去下载：

```
https://storage.googleapis.com/flutter_infra_release/flutter/
  <engine-revision>/linux-riscv64/artifacts.zip
```

**这个文件不存在**，服务器返回 404。Flutter 从未发布 riscv64 Linux 产物。

所以要么自建，要么走 CLI / 网页直传那两条路。

---

## 二、完备性检查清单

flutter 按 `_getEngineArtifactsPath()` 决定目录：

```dart
// mode == debug || mode == null  →  linux-riscv64
// mode != debug                  →  linux-riscv64-<mode>
```

所以 `artifacts/engine/linux-riscv64/`（debug + 宿主工具）和
`artifacts/engine/linux-riscv64-release/` 两个目录各需要：

| 文件 | 用途 | 缺失时的症状 |
|---|---|---|
| `libflutter_linux_gtk.so` | 应用链接的库 | 链接失败 |
| `icudtl.dat` | ICU 数据 | 运行时失败 |
| `flutter_linux/*.h` | 26 个公开头（含 umbrella） | `'flutter_linux/flutter_linux.h' file not found` |
| `gen_snapshot` | AOT 编译器 | `Failed to find ".../linux-riscv64-release/gen_snapshot"` |
| `impellerc` | 着色器编译器 | 着色器编译失败 |
| `shader_lib/` | impellerc 的头文件 | `'#include' : Included file not found. for header name: flutter/runtime_effect.glsl` |
| `font-subset` | 图标字体裁剪 | `IconTreeShakerException: The font-subset utility is missing` |
| `frontend_server_aot.dart.snapshot` | 决定 kernel 的 SDK hash | `Can't load Kernel binary: Invalid SDK hash` |
| `dart-sdk`（`.. /cache/dart-sdk`） | 全链一致的 Dart | `Wrong full snapshot version` |

### `shader_lib` 必须紧邻 `impellerc`

```dart
// shader_compiler.dart:223
final String shaderLibPath = _fs.path.join(impellerc.parent.absolute.path, 'shader_lib');
```

放错位置没用，必须同级。

---

## 三、Dart SDK 必须全链同版本

这是最容易忽略、也最难自查的一条。以下五者**必须同一个 3.15.0-xx.dev**：

```
dart              (bin/dart)
dartaotruntime    (bin/dartaotruntime)
dartvm            (bin/dartvm)
gen_snapshot      (artifacts/engine/*/gen_snapshot)
引擎 .so 内含的 Dart VM
```

外加两个快照也要用同版本 SDK 编出来：

- `flutter_tools.snapshot`（flutter 工具本体）
- `frontend_server_aot.dart.snapshot`（决定 kernel 的 SDK hash）

### 怎么自查

```bash
C=$FLUTTER_ROOT/bin/cache
$C/dart-sdk/bin/dart --version
$C/dart-sdk/bin/dartaotruntime --version
$C/dart-sdk/bin/dartvm --version
$C/artifacts/engine/linux-riscv64-release/gen_snapshot --version
$FLUTTER_ROOT/bin/flutter --version | grep Tools
```

最后一行应当显示 `Tools • Dart 3.15.0 (build 3.15.0-xx.dev)`。

**五个数字有一个不一样，就会出问题。** 我们踩过的具体表现：

| 现象 | 原因 |
|---|---|
| `Can't load Kernel binary: Invalid SDK hash` + 窗口黑屏 | `frontend_server` 版本 ≠ 引擎 VM 版本 |
| `ERROR: ApiError` / AOT exit 254 | `gen_snapshot` 版本 ≠ `app.dill` 里的 hash |
| `Wrong full snapshot version, expected '9190...' found '79a4...'` | `flutter_tools.snapshot` 或 `dart` 与 VM 不同版本 |

### 一个隐蔽的陷阱

`sdk/version` 文件可能写着新版本，而 `bin/` 下的二进制是旧版本。
**文件内容和二进制实际版本不自洽**，看文件会被骗。必须实际执行 `--version`。

我们这台就是这样：所有 dart-sdk 的 `version` 文件都写 `3.15.0-51.0.dev`，
但 `bin/dart` 跑出来是 `3.15.0-40.0.dev`。

## 四、`--local-engine` 只是「引擎不完备」时的绕路

如果引擎 artifact 没铺进 cache，可以用参数直接指过去：

```bash
flutter build linux --release \
  --local-engine-src-path=/path/to/engine/src \
  --local-engine=riscv64-release \
  --local-engine-host=riscv64-release
```

`cache.dart` 里有短路逻辑，能跳过 artifact 校验：

```dart
if (isLocalEngine && artifact is EngineCachedArtifact) { ... }
```

**但这不是终点**，而且有三个代价：

1. `flutter pub get` **不认**这三个参数，仍会去下载、仍会 404
2. release 的 kernel hash 仍需手改（`frontend_server` 版本问题不因这个参数消失）
3. `gen_snapshot` 仍需套包装

我们最终放弃了这条路，把 artifact 补齐 + SDK 统一，从此不需要任何参数。

## 五、还需要伪造缓存 stamp

即便引擎完备，`pub get` 仍会检查 `bin/cache/<name>.stamp` 内容是否等于
`cache.engineRevision`，不等就触发下载（然后 404）。

```bash
C=$FLUTTER_ROOT/bin/cache
V=$(cat $C/engine.stamp)          # 例：57d5122cd9dcfd0174ba963e61df20a328378c64
for n in font-subset flutter_sdk linux-sdk engine engine-dart-sdk; do
  echo "$V" > $C/$n.stamp
done
```

对应 `flutter_cache.dart` 里三个类：`FlutterSdk`（`flutter_sdk`）、
`LinuxEngineArtifacts`（`linux-sdk`）、`FontSubsetArtifacts`（`font-subset`）。
它们都 `extends EngineCachedArtifact`，`version` 都取 `cache.engineRevision`。

还要确保这些目录存在（`isUpToDateInner` 会检查）：

```
bin/cache/pkg/{sky_engine,flutter_gpu}
bin/cache/artifacts/engine/common/{flutter_patched_sdk,flutter_patched_sdk_product}
bin/cache/artifacts/engine/linux-riscv64{,-profile,-release}
```

`flutter --version` 若报 `0.0.0-unknown`，说明 clone 没有 git tag：

```bash
cd $FLUTTER_ROOT && git tag -f 3.41.0
```

## 六、还没解决的两点

诚实记录，避免别人以为一切都好：

1. **`linux-riscv64-profile/` 是空的** —— 没有 profile 引擎，
   `flutter build linux --profile` 会失败。
2. **从未做过从零干净重建** —— 我们的构建是从已有 `out/` 目录做增量。
   换一台干净机器按文档走能否成功，**未验证**。

第 2 点很重要：「装好就能用」不等于「可复现」。
