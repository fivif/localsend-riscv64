# 10 个坑

从「GUI 走不通」到「GUI 跑起来并传完文件」，一共 10 个坑。按遇到顺序。

**核心 CLI 一行都没改** —— 所有问题都在构建链上。

---

## 坑 1 · flutter CLI 起不来：偷下不存在的 Dart SDK

```
Downloading Linux riscv64 Dart SDK from Flutter engine 57d5122c...
End-of-central-directory signature not found
```

`bin/internal/update_dart_sdk.sh` 检查 `bin/cache/engine-dart-sdk.stamp`，
不存在就去下 `linux-riscv64/dart-sdk.zip` —— **官方没这个文件**，返回 259 字节错误页。

```bash
C=$FLUTTER_ROOT/bin/cache
V=$(cat $C/engine.stamp)
cp -a /path/to/riscv64/dart-sdk $C/dart-sdk
echo "$V" > $C/engine-dart-sdk.stamp
printf '' > $C/engine.realm
```

注意是 `engine-dart-sdk.stamp`，不是 `engine.stamp`。两个都叫「引擎」但用途不同。

## 坑 2 · `0.0.0-unknown` 导致版本约束失败

```
The current Flutter SDK version is 0.0.0-unknown.
Because localsend_isolates requires Flutter SDK version ^3.41.0, version solving failed.
```

flutter 从 `git describe --tags` 取版本，clone **没有 tag**。

```bash
cd $FLUTTER_ROOT && git tag -f 3.41.0 && rm -f bin/cache/flutter.version.json
```

⚠️ 这是**贴标签**，不是真的 3.41.0 发布版。

## 坑 3 · 引擎 artifact 404

```
Failed to download .../linux-riscv64/artifacts.zip
Exception: 404
```

`Cache.isUpToDate` 要求 `bin/cache/<stampName>.stamp` 内容等于 `cache.engineRevision`，
不等就触发下载，而 riscv64 的 zip 不存在。

```bash
C=$FLUTTER_ROOT/bin/cache
V=$(cat $C/engine.stamp)
for n in font-subset flutter_sdk linux-sdk engine engine-dart-sdk; do echo "$V" > $C/$n.stamp; done
```

`pub get` 不认 `--local-engine`，所以这一步**必须先做**。

## 坑 4 · pub 依赖三方打架

```
Because flutter_test 0.0.0 from sdk depends on both test_api 0.7.15 and matcher 0.12.20,
test >=1.30.0 <1.31.2 is incompatible with flutter_test 0.0.0 from sdk.
... freezed 3.2.5 which depends on analyzer >=9.0.0 <11.0.0 ...
```

LocalSend 的 `dev_dependencies`（`test ^1.30.0` / `freezed` / `dart_mappable_builder`）
和本 SDK revision 的 `flutter_test` 钉版不兼容。**这是版本偏移，与 riscv64 无关。**

生成代码都已提交（31 个 `*.mapper.dart`、4 个 `*.freezed.dart`、60 个 `*.g.dart`），
构建不需要 codegen。临时剥离全部 `dev_dependencies` 即可，**备份务必留着**。

## 坑 6 · cargokit 不认识 `linux-riscv64`

```
SEVERE: Cargokit BuildTool failed with error:
SEVERE: Exception: Unknown target platform: linux-riscv64
```

`target.dart` 的映射表只有 `linux-x64` / `linux-arm64`。
`build_cmake.dart:23` 拿不到 target 就抛异常。见 `patches/0001`。

**为什么用 `riscv64a23`**：板子 rustc 是 SpacemiT 定制工具链，
`$(rustc --print sysroot)/lib/rustlib/` 下只有它一个 triple 有 std，且没有 rustup。
通用环境请用 `riscv64gc-unknown-linux-gnu`，见 `patches/0003`。

## 坑 7 · 引擎头文件目录是空的

```
fatal error: 'flutter_linux/flutter_linux.h' file not found
```

CMake 的 include 路径是 `app/linux/flutter/ephemeral`，要找
`ephemeral/flutter_linux/flutter_linux.h`。这个目录**空的** ——
引擎 make 目标没跑头文件拷贝（只编了 `.so`）。

```bash
P=$ENGINE_SRC/flutter/shell/platform/linux/public/flutter_linux
cp -a $P/*.h app/linux/flutter/ephemeral/flutter_linux/
cp -a $P/*.h $ENGINE_SRC/out/riscv64-release/flutter_linux/   # 这个也是空的
```

26 个文件，含 umbrella `flutter_linux.h`。

## 坑 8 · 弃用警告被升成错误

```
error: 'app_indicator_new' is deprecated [-Werror,-Wdeprecated-declarations]
```

`tray_manager` 自带 `-Werror`，而 ayatana 把 `app_indicator_new` 标了 deprecated。

在 `app/linux/CMakeLists.txt` 里、`include(flutter/generated_plugins.cmake)`
**之前**加（必须在前面才能传播到插件子目录）：

```cmake
add_compile_options(-Wno-error=deprecated-declarations)
```

见 `patches/0002`。

## 坑 9 · kernel SDK hash 不匹配（debug 版）

现象：**进程活着、窗口在、屏幕全黑。**

```
[ERROR] Dart Error: Can't load Kernel binary: Invalid SDK hash.
[ERROR] Could not prepare isolate.
[ERROR] Could not create root isolate.
```

`kernel_blob.bin` 是多段 dill 顺序拼接，**每段都有自己的 10 字节 header**。

只改第一个 → 第 2 段往后仍失败，同样报 `Invalid SDK hash`。

我们的情况：`frontend_server` 写 `5521341774`（40.0.dev），引擎 VM 期望
`69672e35b9`（51.0.dev）。

```bash
python3 patch-kernel-hash.py kernel_blob.bin 69672e35b9
# → written: 177 header(s) patched
```

工具见 `engine-notes/`。源码里的 `kernel_loader.cc` 的 `index_programs()`
支持 dill 拼接，所以扫描必须扫全部 magic，一个都不能漏。

## 坑 10 · AOT snapshotter `ApiError` / exit 254（release 版）

```
ERROR: ApiError
ERROR: Dart snapshot generator failed with exit code 254
ERROR: Target aot_snapshot_release failed
```

同样是 hash 不匹配，但这次发生在 `gen_snapshot` 校验 `app.dill`。

**失败的尝试**：手动改 `app.dill` 的 hash，然后单独跑 `gen_snapshot` ——
成功了，产出 15.7 MB `app.so`，耗时约 4 分钟。

**但 `flutter build` 会重新跑 `frontend_server`，把 `app.dill` 覆盖回旧 hash**，
手改无效。

**解法**：给 `gen_snapshot` 套包装，每次调用前先修正输入 dill 的 hash：

```bash
cd $ENGINE_SRC/out/riscv64-release
cp -a gen_snapshot gen_snapshot.real
cat > gen_snapshot <<'WRAP'
#!/bin/bash
REAL="$(dirname "$(readlink -f "$0")")/gen_snapshot.real"
IN=""
for a in "$@"; do case "$a" in -*) ;; *) IN="$a" ;; esac; done
[ -n "$IN" ] && [ -f "$IN" ] && python3 /path/to/patch-kernel-hash.py "$IN" 69672e35b9 >/dev/null 2>&1
exec "$REAL" "$@"
WRAP
chmod +x gen_snapshot
```

包装对调试透明：`./gen_snapshot --version` 仍正常输出。

## 附 · release 还要关图标裁剪

```
ERROR: IconTreeShakerException: The font-subset utility is missing.
```

加 `--no-tree-shake-icons`。代价是 Material 图标字体不被裁剪，包体略大。
