# 上游建议版：改用标准 Rust triple

`0001-cargokit-riscv64.patch` 里用的是 **`riscv64a23-unknown-linux-gnu`**。
**这是本地妥协，不要照抄推上游。**

## 为什么本地用了它

板子的 Rust 工具链是 SpacemiT 定制的：

```
$ rustc -vV
host: riscv64a23-unknown-linux-gnu
release: 1.93.1

$ ls $(rustc --print sysroot)/lib/rustlib/
etc  riscv64a23-unknown-linux-gnu      ← 只有这一个有 std

$ which rustup
（不存在）
```

没有 rustup，装不了 `riscv64gc-unknown-linux-gnu` 的 std，
所以只能用宿主 triple 才能编译。

## 推上游应该这样写

标准 Rust riscv64 Linux triple 是 `riscv64gc-unknown-linux-gnu`。
cargokit 上游的补丁应该是：

```diff
     Target(
       rust: 'aarch64-unknown-linux-gnu',
       flutter: 'linux-arm64',
     ),
+    Target(
+      rust: 'riscv64gc-unknown-linux-gnu',
+      flutter: 'linux-riscv64',
+    ),
     Target(
       rust: 'x86_64-apple-darwin',
```

以及 `buildableTargets()`：

```diff
       if (arch.trim() == 'aarch64') {
         return [Target.forRustTriple('aarch64-unknown-linux-gnu')!];
+      } else if (arch.trim().startsWith('riscv64')) {
+        return [Target.forRustTriple('riscv64gc-unknown-linux-gnu')!];

```

## 上游仓库在哪

cargokit 是 **vendored** 进 `flutter_rust_bridge` / LocalSend 的，
改 LocalSend 里的副本对上游没有意义。真正的上游是 cargokit 自己的仓库。

提 PR 前先确认两点：

1. 许可证与贡献流程（各仓库不同）
2. 上游目标版本里 `Target` 类的字段是否还是 `rust` / `flutter` 这两个名字

## 双方都能用的写法

如果希望一份补丁同时覆盖两种环境，可以让 triple 可配置，例如
优先读环境变量、回退到标准 triple：

```dart
static String get _riscvTriple =>
    Platform.environment['CARGOKIT_RISCV64_TRIPLE'] ??
    'riscv64gc-unknown-linux-gnu';
```

这样 Bianbu 这类定制工具链的用户可以设
`CARGOKIT_RISCV64_TRIPLE=riscv64a23-unknown-linux-gnu`，
而通用环境什么都不用配。

（上面这段是建议方案，**本仓库未实现、未测试**。）
